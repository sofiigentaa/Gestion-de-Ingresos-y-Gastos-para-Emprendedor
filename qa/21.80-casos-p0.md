# 21.80 — Casos P0 de Gestión de ingresos y gastos

Versión 0.1 del 2026-11-18. Veintinueve casos P0 redactados contra el documento funcional v1.0 y el commit `6692d9f`.
**Nadie ejecutó la aplicación: ningún caso tiene resultado observado.** Los esperados salen del documento (`[D]`), del
código cuando el documento calla (`[C]`) o quedan por confirmar con el equipo (`[A]`). Un `[C]` que difiera de lo que se
observe no es un defecto por sí solo: se consulta al equipo antes (ver "Observaciones previas" en el plan).

Plan: `21.80-plan-de-pruebas.md` (datos `DS-01`, `DS-02`, `DS-03`, ambientes, observaciones `OBS-nn`).

## Cómo leer los casos

- **F** es la fecha de ejecución, AAAA-MM-DD. Los casos con "hoy", "ayer" o "anteayer" se calculan respecto de F.
- Ambiente por defecto: **local** (`npm run dev`, `http://localhost:3000`), Chrome de escritorio. Los casos `SES-*` y
  `MOV-06` exigen **nube** con cuentas A y B. Si F no cae en 2026-11, las vistas mensuales se leen en el mes 2026-11
  con las flechas del selector de mes.
- Los importes de pantalla se escriben como la app los formatea: `$ 15.000`, `$ 15.000,5` (hasta dos decimales, sin
  completar ceros, `src/utils/formatters.ts:2-8`). El balance positivo lleva `+` delante.
- Dato de partida `DS-01` cargado con *Exportar & Respaldos → Restaurar Archivo* (plan, sección 5). Cada caso parte de
  `DS-01` recién cargado, salvo que diga otra cosa. Cada caso de aprendizaje parte de un **perfil de navegador limpio**.
- Mensajes de la app entre comillas: se copian de `src/`; si el texto observado difiere, se registra el texto observado.
- Después de cada rechazo (monto inválido, archivo inválido, confirmación cancelada) se comprueba que **nada cambió**:
  cantidad de movimientos, totales y, en local, el arreglo guardado en `localStorage`.

## Registro de evidencia

Por cada ejecución: ID de caso, producto, commit, ambiente, navegador y versión, F, preparación y datos, pasos, esperado,
observado, evidencia, defecto asociado, responsable y fecha. Nombre de archivo de evidencia:
`IYG-XXX-NN_AAAA-MM-DD_paso-NN.png` (o `.json`, `.csv`, `.webm`). Evidencia mínima: captura de pantalla con fecha y hora
visibles de cada paso con resultado relevante. Nunca capturar contraseñas ni cabeceras de autorización: ocultarlas.

Para los casos de aprendizaje, además: volcado de `localStorage` (clave `golondrina:germania-finanzas`) antes y después
de cada fase, con la hora de cada acción. Cómo obtenerlo: DevTools (F12) → *Application* → *Local Storage* → origen de
la app → clave → copiar el valor; o en la consola `copy(localStorage.getItem('golondrina:germania-finanzas'))`.
Campos que se miran: `habitos` (cada entrada con `total`, `peso`, `manual`, `asistente`, `golondrina`), `transiciones`
(qué acción siguió a cuál y cuántas veces), `sugerencias` (por clave: `mostrada`, `veces`, `rechazos`, `aceptadas`,
`silenciada`), `silencio`, `frases`, `recientes`.

## IYG-APR-01 — Rutina repetida frente a acciones aisladas
